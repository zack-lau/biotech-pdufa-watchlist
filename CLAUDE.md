## Running the dashboard

A LaunchAgent (`~/Library/LaunchAgents/cc.lzac.pdufa-dashboard.plist`) auto-starts the server at login on port 8000 and restarts it if it crashes. The dashboard is normally always available at `http://localhost:8000/`.

```bash
# Stop / start the service
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/cc.lzac.pdufa-dashboard.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/cc.lzac.pdufa-dashboard.plist

# Check status (shows PID and last exit code)
launchctl list | grep pdufa

# View server logs
tail -f ~/Library/Logs/pdufa-dashboard.log
```

Or for a one-off manual serve (e.g. on a port other than 8000), double-click `start-dashboard.command` in Finder.

The dashboard uses `fetch()` to load JSON files, so it must be served over HTTP (not `file://`).

## Architecture

This is a fully static, no-build-step web app. There is no package.json, no bundler, no test suite.

**Scaffold files (never regenerated by scheduled runs):**
- `index.html` — static shell: header, hero, KPI grid, timeline strip, filter toolbar, four sections (Resolved / High / Medium / Watch / Cards), footer. Each scheduled run bumps the `?v=YYYYMMDD` cache-bust param on the CSS/JS asset tags — that's the only permitted change.
- `base.css` — resets and focus styles
- `style.css` — design tokens, light/dark themes, all component styles (timeline, toolbar, gauges, diff badges, print)
- `app.js` — the entire render layer; fetches `data.json` + `previous-data.json` and hydrates all DOM

**Data files (overwritten each scheduled run):**
- `data.json` — current run output; the source of truth for the dashboard
- `previous-data.json` — prior run's data.json; used by app.js to compute run-over-run delta badges (NEW, rating change, approval-odds Δ, short-interest Δ, date moved)

## app.js render flow

1. `Promise.all([fetch data.json, fetch previous-data.json])` → calls `render(data, prev)`
2. Populates hero eyebrow/title/lede, KPI grid, and PDUFA timeline strip from top-level `data` fields
3. Splits `data.tickers` into HIGH / MEDIUM / WATCH buckets by `rating` field; renders tables for HIGH and MEDIUM, compact table for WATCH, full cards grid at bottom
4. Renders `data.resolved[]` in the Resolved section
5. Wires filter chips, sort select, search input, star/hide buttons, `.ics` export, and `#TICKER` deep-link scroll
6. Star/Hide state persists in `localStorage` under key `pdufa-watchlist-state` (browser-local only)
7. Theme (light/dark) persists in `localStorage` under key `pdufa-theme`

Keyboard shortcuts: `/` focuses search; `#TICKER` in URL scrolls to that card on load.

## data.json schema

Top-level fields: `lastUpdated`, `timezone`, `runId`, `heroEyebrow`, `heroTitle`, `calendarNote`, `summary` (counts), `resolved[]`, `tickers[]`.

`heroLede` is intentionally optional — the renderer falls back to `calendarNote` when it's absent. Only set `heroLede` for partial-run warning banners (it overrides `calendarNote`).

Each ticker object includes: `ticker`, `company`, `drug`, `indication`, `rating` (high/medium/watch), `pdufaDate`, `pdufaDatesExtra[]`, `applicationType`, `nme/priorityReview/btd/fastTrack/adcom`, `approvalOdds`, market data (`price`, `marketCap`, `shortInterest`, `iv`, `analystPT` with `*AsOf` dates), `drugProfile` (prose; `<strong>` allowed), `bull[]`/`bear[]`/`risk[]` (arrays of one-sentence strings, no HTML), sentiment objects (`xSentiment`, `redditSentiment`, `googleTrends`), `insider`, `priceChange`, `cashRunway`, `sponsorTrackRecord`, `sources[]`.

`sources[]` entries must have both `name` and `url`; app.js uses `s.name` as link text.

`pdufaDatesExtra[]` entries use two label conventions:
- `"2026-07-26 — Drug name"` — same ticker, second PDUFA date
- `"2026-07-15 — alt source: FierceBiotech"` — conflicting date from a different source

## Scheduled data refresh

Runs Mon/Wed/Fri 06:00 SGT. The full autonomous agent prompt lives in `scheduled-task-prompt.md` — read it before modifying any data-layer behavior. Key pipeline steps:

1. Discover PDUFA tickers in the next 90-day window (Perplexity + BioPharma Catalyst + searxng)
2. Validate each ticker via yfinance (USD, US exchange, $50M–$10B market cap)
3. Per-ticker deep research (drug profile, bull/bear/risk, sentiment, market data, cash runway, sponsor track record) using Perplexity, xAI/X search, Clinical Trials MCP, yfinance, MarketBeat via markitdown
4. Copy current `data.json` → `previous-data.json`, then write new `data.json`
5. Validate JSON with `python3 -c "import json; json.load(open('data.json'))"`

`web_fetch` is blocked for most biotech/IR/SEC/FDA URLs in the scheduled environment; use `markitdown__convert_to_markdown` as the canonical URL reader instead.

## Modifying the dashboard

- **UI changes** go in `style.css` (tokens/layout) or `app.js` (rendering logic); `index.html` only needs changes for new static structural sections.
- **Data schema changes** require updating both `app.js` (renderer) and `scheduled-task-prompt.md` (agent schema spec) together.
- **Do not add a build step** — the project is intentionally dependency-free.

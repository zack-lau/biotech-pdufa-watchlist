## Running the dashboard

A LaunchAgent (`~/Library/LaunchAgents/cc.lzac.pdufa-dashboard.plist`) auto-starts the server at login on port 8000 and restarts it if it crashes. The dashboard is normally always available at `http://localhost:8000/`.

```bash
# Stop / start the service
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/cc.lzac.pdufa-dashboard.plist
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/cc.lzac.pdufa-dashboard.plist

# Check status (shows PID and last exit code)
launchctl list | grep pdufa

# View server logs
tail -f ~/Library/Logs/pdufa-dashboard.log
```

Or for a one-off manual serve (e.g. on a port other than 8000), double-click `start-dashboard.command` in Finder.

The dashboard is a React + Next.js app. It must be served by Next.js over HTTP; opening files directly with `file://` will not work.

## Architecture

This is a React + Next.js App Router dashboard. It keeps the data-refresh workflow file-based, with no backend database and no external write target.

**Scaffold files (never regenerated by scheduled runs):**
- `package.json` / `package-lock.json` — Next.js, React, and npm scripts.
- `next.config.mjs` — minimal Next.js configuration.
- `app/layout.jsx` — global metadata, font links, and CSS imports.
- `app/page.jsx` — server component that reads root `data.json` and `previous-data.json` on each request and passes them into the dashboard.
- `app/Dashboard.jsx` — client component for the full interactive render layer.
- `base.css` — resets and focus styles
- `style.css` — design tokens, light/dark themes, all component styles (timeline, toolbar, gauges, diff badges, print)
- `serve.py` — LaunchAgent entrypoint that starts `npm run dev -- -H 0.0.0.0 -p 8000`
- `start-dashboard.command` — manual Next.js launcher

**Data files (overwritten each scheduled run):**
- `data.json` — current run output; the source of truth for the dashboard
- `previous-data.json` — prior run's data.json; used by `app/Dashboard.jsx` to compute run-over-run delta badges (NEW, rating change, approval-odds delta, short-interest delta, date moved)

## React render flow

1. `app/page.jsx` reads `data.json` and `previous-data.json` from the project root with Node `fs`.
2. Populates hero eyebrow/title/lede, KPI grid, and PDUFA timeline strip from top-level `data` fields
3. Splits `data.tickers` into HIGH / MEDIUM / WATCH buckets by `rating` field; renders tables for HIGH and MEDIUM, compact table for WATCH, full cards grid at bottom
4. Renders `data.resolved[]` in the Resolved section
5. `app/Dashboard.jsx` wires filter chips, sort select, search input, star/hide buttons, `.ics` export, and `#TICKER` deep-link scroll
6. Star/Hide state persists in `localStorage` under key `pdufa-watchlist-state` (browser-local only)
7. Theme (light/dark) persists in `localStorage` under key `pdufa-theme`

Keyboard shortcuts: `/` focuses search; `#TICKER` in URL scrolls to that card on load.

## data.json schema

Top-level fields: `lastUpdated`, `timezone`, `runId`, `heroEyebrow`, `heroTitle`, `calendarNote`, `summary` (counts), `resolved[]`, `tickers[]`.

`heroLede` is intentionally optional — the renderer falls back to `calendarNote` when it's absent. Only set `heroLede` for partial-run warning banners (it overrides `calendarNote`).

Each ticker object includes: `ticker`, `company`, `drug`, `indication`, `rating` (high/medium/watch), `pdufaDate`, `pdufaDatesExtra[]`, `applicationType`, `nme/priorityReview/btd/fastTrack/adcom`, `approvalOdds`, market data (`price`, `marketCap`, `shortInterest`, `iv`, `analystPT` with `*AsOf` dates), `drugProfile` (prose; `<strong>` allowed), `bull[]`/`bear[]`/`risk[]` (arrays of one-sentence strings, no HTML), sentiment objects (`xSentiment`, `redditSentiment`, `googleTrends`), `insider`, `priceChange`, `cashRunway`, `sponsorTrackRecord`, `sources[]`.

`sources[]` entries must have both `name` and `url`; `app/Dashboard.jsx` uses `s.name` as link text.

`pdufaDatesExtra[]` entries use two label conventions:
- `"2026-07-26 — Drug name"` — same ticker, second PDUFA date
- `"2026-07-15 — alt source: FierceBiotech"` — conflicting date from a different source

## Heartbeat data refresh

The refresh is run by a Codex heartbeat named `biotech-pdufa-watchlist`, attached to this thread, on Mon/Wed/Fri at 06:00 SGT. `AGENTS.md` is the source of truth for the run. Do not depend on `scheduled-task-prompt.md`; it is archival only.

At the start of every refresh:

1. Resolve today's date in Singapore time with `TZ=Asia/Singapore date +%Y-%m-%d`.
2. Work only in `/Users/zack/Documents/Codex/PDUFA`.
3. Do not write to Google Drive, Dropbox, Box, iCloud, GitHub, email, or any folder outside this project.
4. Preserve scaffold files. A routine data refresh should not edit React, CSS, package, launcher, or legacy static files.

Allowed scheduled-run writes:

- Copy current `data.json` to `previous-data.json`.
- Write a new `data.json`.
- Do not touch `base.css`, `style.css`, `app/`, `package.json`, `package-lock.json`, `serve.py`, `start-dashboard.command`, `index.html`, or `app.js` during a data refresh unless the user explicitly asks for UI or runtime changes.

### Tool expectations and fallbacks

Preferred tools:

- Perplexity: discovery, PDUFA confirmation, synthesis, approval-probability consensus, sponsor track record.
- searxng: supplementary discovery, Reddit discovery, FDA/SEC/Fierce/source discovery.
- markitdown: canonical URL reader for press releases, SEC/FDA pages, MarketBeat, ClinicalTrials.gov pages, and PDFs.
- yfinance: ticker validation, price, market cap, analyst target, options, financials, price history.
- xAI/X search: `xSentiment`.
- Telegram MCP: send the completion notification after every heartbeat refresh.

Known Codex tool gaps from the dry run:

- ClinicalTrials MCP may be unavailable. If it is unavailable, use Perplexity plus markitdown on `https://clinicaltrials.gov/study/{NCT}` when an NCT ID is found. Write `"Unknown"` for trial fields that cannot be sourced.
- Reddit URLs may return empty content through markitdown. If searxng finds Reddit threads but markitdown returns empty/failed content, write `redditSentiment.overall = "Unavailable"`, `volume = "Low"`, and summarize that Reddit content could not be read.
- yfinance price history can include partial current-day rows with `NaN` OHLC. Skip invalid rows before computing price changes.
- yfinance near-expiry option chains can include zero bid/ask and placeholder IV. Use the nearest valid ATM contract with nonzero/open-interest data; otherwise set `iv = "Unknown"`.
- Perplexity deep research can be slow and verbose. Ask for citations, then extract only the fields needed for `data.json`.

Avoid `web_fetch` for biotech / IR / FDA / SEC URLs; use markitdown instead. If markitdown fails, try another source URL rather than retrying the same blocked URL.

### Refresh pipeline

1. Discover every US-listed small- and mid-cap biotech with an FDA PDUFA target action date in the next 90 days.
2. Include NDAs, BLAs, sNDAs, sBLAs, and ANDAs where relevant.
3. Exclude sponsors with market cap `>= $10B`.
4. Validate each candidate with yfinance:
   - `currency == "USD"`
   - `quoteType == "EQUITY"`
   - US exchange in `NMS`, `NGM`, `NGS`, `NCM`, `NYQ`, `NYSE`, `NCS`, `ASE`, `AMEX`
   - `50_000_000 <= marketCap < 10_000_000_000`
5. Resolve conflicting PDUFA dates by authority: company press release / 8-K > FDA.gov > BioPharma Catalyst > Fierce Biotech > Perplexity narrative.
6. Put conflicting alternate dates in `pdufaDatesExtra[]` as `"YYYY-MM-DD — alt source: SourceName"`.
7. For multiple valid PDUFA dates for the same ticker, use the earliest as `pdufaDate` and put the rest in `pdufaDatesExtra[]` as `"YYYY-MM-DD — Drug or program name"`.
8. Carry forward prior `resolved[]` entries unless `resolvedDate` is more than 30 days before today.
9. Move newly decided past-date entries into `resolved[]` with lightweight outcome research only.

Rating rules:

- `high`: PDUFA within 7 days.
- `medium`: PDUFA 8-56 days out.
- `watch`: PDUFA more than 56 days out.

### Per-ticker fields

For every tracked ticker, populate:

- Identity: `ticker`, `company`, `drug`, `indication`, `rating`, `pdufaDate`, `pdufaDatesExtra[]`, `applicationType`.
- Regulatory flags: `nme`, `priorityReview`, `btd`, `fastTrack`, `adcom`.
- Thesis: `approvalOdds`, `drugProfile`, `bull[]`, `bear[]`, `risk[]`.
- Market data: `price`, `priceAsOf`, `marketCap`, `shortInterest`, `shortInterestAsOf`, `iv`, `ivAsOf`, `analystPT`, `analystPTAsOf`.
- Sentiment: `xSentiment`, `redditSentiment`, `googleTrends`, `insider`.
- Analytics: `priceChange`, `cashRunway`, `sponsorTrackRecord`.
- Sources: `sources[]`.

Field rules:

- Use `"Unknown"` when a string value cannot be reliably sourced.
- Use `null` for unknown numeric nested values.
- `bull`, `bear`, and `risk` are arrays of one-sentence strings. Do not embed HTML.
- `drugProfile` may use `<strong>` only; no other HTML.
- `sources[]` entries must have both `name` and `url`.
- `googleTrends` is always unavailable until a Trends-capable tool exists:
  `{ "signal": "Unavailable", "volume": "Low", "peakDate": "", "summary": "No Google Trends MCP available in this environment." }`

### Output file rules

Before writing:

1. Read current `data.json`.
2. Copy its exact contents to `previous-data.json`.
3. Increment the run number from `previous-data.json`'s `runId` or, if needed, from `calendarNote`.

New `data.json` top-level fields:

- `lastUpdated`: today's SGT date in `YYYY-MM-DD`.
- `timezone`: `Asia/Singapore`.
- `runId`: `Run #N (Mmm D SGT)`.
- `heroEyebrow`: `Weekday, D Month YYYY (SGT) · Run #N`.
- `heroTitle`: `US-listed small & mid-cap biotechs with PDUFA dates in the next 90 days`.
- `calendarNote`: one-line run summary starting with `Run #N (Mmm D SGT). X HIGH, Y MEDIUM, Z WATCH.`
- `summary`: counts for `tracked`, `high`, `medium`, `watch`, `resolved`.
- `resolved`: sorted ascending by `resolvedDate`.
- `tickers`: sorted ascending by `pdufaDate`.

Only include `heroLede` on partial runs. Prefix partial-run copy with `Partial run - ` so the dashboard visibly surfaces the issue.

After writing:

1. Validate JSON with `python3 -c "import json; json.load(open('data.json'))"`.
2. Confirm `summary` counts match the arrays.
3. Confirm `http://localhost:8000/` responds if the LaunchAgent is running. Next.js reads the JSON files dynamically, so no cache-bust edit is required.

Final heartbeat reply:

- Link to `http://localhost:8000/`.
- One paragraph under 80 words summarizing total tracked, count by rating, new tickers, dropped tickers, rating changes, and approval-odds moves over 5 percentage points.
- List unavailable sources/tools.
- If partial, state exactly what failed and what data was still refreshed.

Telegram notification:

- After the refresh is complete and `data.json` has validated, send a Telegram message with `mcp__telegram_mcp.send_message`.
- Use `chat_id = "496920142"`.
- Use plain text unless formatting is necessary.
- Include `http://localhost:8000/`, the run ID, tracked count by rating, and any unavailable sources/tools.
- If the run is partial, start the Telegram message with `Partial PDUFA refresh:` and include the failure reason.
- If Telegram send fails, do not retry in a loop; mention the Telegram failure in the final heartbeat reply.

## Modifying the dashboard

- **UI changes** go in `style.css` (tokens/layout) or `app/Dashboard.jsx` (rendering logic); `app/layout.jsx` and `app/page.jsx` only need changes for app shell or data-loading behavior.
- **Data schema changes** require updating both `app/Dashboard.jsx` (renderer) and this `AGENTS.md` schema spec together.
- **Runtime changes** require validating `npm run build`, then restarting the LaunchAgent if port 8000 behavior changes.
